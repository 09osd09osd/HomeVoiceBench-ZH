# 数字与单位如何朗读

三个被测系统统一使用 `homevoice/speech_text.py` 中的 `zh_spoken_v1`。模型先产生原始回答，程序将数字和常见单位改成中文读法，再交给语音生成部分。实验组仍使用自己的原生 talker；两条基线使用本地 Qwen3-TTS-0.6B。

| 原始写法 | 实际送去朗读的文字 |
|---|---|
| 122 | 一百二十二 |
| 26℃ | 二十六摄氏度 |
| 40% | 百分之四十 |
| 07:30 | 七点三十分 |
| 20-30℃ | 二十到三十摄氏度 |
| 2026年12月1日 | 二零二六年十二月一日 |

规则也覆盖小数、正负数、千分数、ppm、日期时间、常见温度/长度/体积/功率/照度单位，以及需要逐位保留的手机号和标识符。完整覆盖范围以函数和测试为准，不宣称能够处理所有语言和任意单位。

转换只作用于可朗读文本。例如调用灯光工具时，`brightness_pct: 40` 仍是数字40；不会把它改成字符串“百分之四十”。用户输入语音的合成同样使用这一转换，编写原稿不作为用户文字输入传给被测模型。

每条实际回答分别保存原文 `assistant_text`、朗读文本 `spoken_text`、规则版本和实际音频。音频判官听的是生成后的声音，不能用转换文本代替发音质量评分。

正式结果的全部7,818个已完成助手轮次经过核对，转换后的朗读文本未残留阿拉伯数字。这个检查证明转换环节被执行，不表示每个音频都已正确发音。逐系统统计见[结果报告](RESULTS.md)。

另有一个不计入正式1,000题的原生语音专项样例：

> 原文：编号122，温度26℃，亮度40%，时间07:30。  
> 朗读稿：编号一百二十二，温度二十六摄氏度，亮度百分之四十，时间七点三十分。

该样例经过指定判官实际听音核查，通过了这组指定数字和单位的读法检查；尚未人工审核。可在[交互网页](index.html#pipeline)展开试听，原始核查记录见[normalization_audio_pilot.json](../reports/normalization_audio_pilot.json)。
