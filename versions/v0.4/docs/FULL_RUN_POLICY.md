# v0.4 正式运行前固定的评分与执行口径

2026-11-18，用户指示“按你修复后的标准来吧，全量运行，加快速度啊”，取代此前等待人工校准的安排。人工标签没有被填写或冒充；本轮是机器评分，仍有同模型偏差的限制。

## 任务通过

1. 正常完成执行，必需的程序检查全部通过。逐轮、逐对象、逐字段、逐允许值核对每次写入；等价时间按语义比较；聊天允许相关只读查询。
2. Qwen3.8-Omni-Flash 实际听用户及回答语音，温度0，判断 CONTENT 与 HONEST。只把用户真正要求的事项作为硬约束；开放式答案不用复刻参考。六维质量另报，不用每维最低分卡通过。
3. 对所有有听音初判的记录统一做语义一致性复核，隐藏初判标签、理由和模型身份。此阶段读取初判听写，不称为第二次独立听音。
4. 两次通过结论有分歧，或独立ASR与听写的闭合数值核对需要复查时，进行一次新的原音频裁定。它看不到此前标签、理由、转写和模型身份。第一份结构合法的结果为最终语义结论；格式/网络重试不能挑选较高分。客观规则失败仍然失败。
5. 原始初判、语义复核、重新听音裁定、数值依据全部保留。没有实际回答音频的执行失败记任务失败，质量分不伪造为零。

脚本：`judge_runs.py` → `review_semantics.py` → `check_audio_facts.py` → `adjudicate_audio.py`。同样方法应用于所有系统，禁止按模型或预期通过率选用不同口径。

## source-wording-repair

100题开发集中 T06_101—104、T11_101—104、T12_101 共9题的用户原稿混入工具字段。只把字段改为自然中文并删除代码翻译括号，不改变数值、对象、执行目标或授权。9题对三组对称重跑。修正前的100题、300份结果、输入输出录音和报告完整保留在 `pilot_history/pre_full_run_protocol`；原始v0.3不变。

正式1000题在生成前从源任务消除这类字段，并在文本审题和冻结输入时再次拦截。文本来自官方DeepSeek API，输入声音仍由指定TTS生成，同题三组使用相同波形。

## 验证与统计边界

正式推理前，须验证全部输入、可执行参考、覆盖比例、greedy参数、修复后的9题、无未解决基础设施错误。开发反例是编码代理审查的诊断用例，不是独立人工金标；反例的不一致必须披露，不能声称人工校准完成，也不把其准确率推广到全部题。

所有规则在正式模型成绩出现之前固定，不以目标通过率作为验收条件。任务、质量、执行失败、评分分歧和再次听音次数分别报告。后续人评可以新增有版本的结果，不能悄悄覆盖本轮证据。

## 并发与缓存

内容与工具决策：三组greedy。Qwen 2B/4B客户端并发8/4，Edge客户端与推理批次8；同一块GPU顺序加载内容骨干，避免相互挤占。云端文本16并发、用户TTS与质检24并发、听音评分24并发。级联TTS按长度分桶，从12动态增至最多32，只在实测显存余量允许时增加；资源失败保存重试原因，不按内容换答案。语音、ASR缓存按内容哈希复用，模型回答不从开发集复用至正式集。
